Benchmark terminology

Definitions for the recorded PhishLens history, including the limits of each statistic.

Mac/macOS evaluation is unmeasured in the audited records. MCC is a separate classification metric. No Windows speed was converted into a Mac estimate.

Reading this history

One CSV row

One statistic, gate result, timing summary or documented event. A row is not one email and is not necessarily a separate inference run.

Example: Recall, FPR and F1 for the same model/cohort are three rows describing the same predictions.

Reading this history

Run and protocol

A run_id identifies a saved execution or reporting stage. A protocol identifies the experimental rules. Pilots, stopped runs, revisions and complete tests remain separate.

Example: A 16-message pilot and a later 500-message run must not be pooled into one test.

Reading this history

UTC and Manila timestamps

UTC is the reference timezone. Manila is UTC+08:00. timestamp_raw preserves the original recorded text. timestamp_role distinguishes execution starts, report generation, import times and dates without a clock.

Example: 23 October at 19:08 UTC is 24 October at 03:08 in Manila.

Reading this history

Missing versus zero

An empty value means unavailable, undefined or not recorded, as explained by availability and status. A numeric zero is an observed or computed zero. Neither is an automatic pass.

Example: No Mac test means blank accuracy, not 0% accuracy.

Reading this history

Recorded versus derived

Recorded values are copied from saved evidence. Derived timing summaries are calculated from existing saved samples using the stated method. No model was rerun to create this history.

Example: A saved sample array can yield a mean and population standard deviation; these are new summaries of old observations.

Reading this history

Source path, pointer and SHA-256

The relative source_path locates the evidence file. source_pointer identifies its JSON field or 1-based CSV line. source_sha256 identifies the exact file content. context_source supplies associated model/environment metadata.

Example: csv-row-2/recall refers to the first data line of a CSV whose header is line 1.

Models and data

TF-IDF + Logistic Regression

TF-IDF turns text into weighted word/ngram features. Logistic Regression learns a classifier from labelled training examples. This is the project's chosen model; selecting it does not make every qualification gate pass.

Example: The benchmarked reference has a validation-selected alert cutoff of 0.6196111742515448.

Models and data

DistilBERT / instruct LLM

DistilBERT is a neural text encoder used with a classification head. An instruct LLM generates a structured answer. Different checkpoints, quantization formats, prompts and runtimes are different tested implementations.

Example: The older Ollama Llama 3B run and the later ONNX Llama 1B run are separate candidates.

Models and data

Positive label

The meaning of label 1 comes from the specific protocol. Some legacy sources include spam and fraud; early three-class tests instead treat spam as non-phishing. These are different prediction tasks.

Example: 98.2% source-positive recall must not be rewritten as 98.2% independently verified credential-phishing recall.

Models and data

Train / validation / calibration / threshold / test

Training learns model parameters. Validation supports development. Calibration fits score interpretation. The threshold cohort chooses the alert boundary. Test inputs evaluate the frozen pipeline.

Example: Changing the cutoff after inspecting test labels contaminates that test.

Models and data

ID / OOD / adversarial

ID is the defined in-distribution test. OOD targets a different intended population. Adversarial evaluation needs validated attack techniques and appropriate legitimate controls. Dataset names alone do not establish these properties.

Example: An HTML-only email is not automatically a deliberately adversarial email.

Models and data

Collected / synthetic / reconstructed

Collected messages originate from received mail. Synthetic text is generated. Reconstructed or translated bodies substantially alter the original content. The history preserves these origins instead of pooling them as authentic evidence.

Example: The 303-input functional comparison cannot replace authentic real-email OOD/bank controls.

Models and data

Deduplication, group and leakage

Exact duplicate inputs are collapsed. Related messages can share a dependency group. Leakage occurs when training/development material or closely related content contaminates the intended held-out test.

Example: The first English revision stopped after overlap with public checkpoint emails; the clean revision excluded entire affected groups.

Models and data

Truncation

The shared later protocol cleans visible text/HTML and whitespace; inputs longer than 2,300 Unicode code points retain the first 2,000 and last 300. Older protocols can use other documented rules.

Example: The constructed submission had no inputs cut under this rule.

Classification statistics

TP / FP / TN / FN

TP: positive correctly alerted. FP: negative wrongly alerted. TN: negative correctly left unalerted. FN: positive missed. Definitions follow that protocol's labels.

Example: The functional TF-IDF result was TP 173, FP 125, TN 5, FN 0.

Classification statistics

Accuracy

Correct decisions divided by all scored examples: (TP+TN)/(TP+FP+TN+FN). Check whether a historical result instead conditions on valid outputs.

Example: TF-IDF functional accuracy: (173+5)/303 = 58.75%.

Classification statistics

Recall / false-positive rate

Recall = TP/(TP+FN), the fraction of positives caught. FPR = FP/(FP+TN), the fraction of negatives wrongly alerted. Both require the stated denominator.

Example: Functional TF-IDF recall was 100%, while its FPR was 125/130 = 96.15%.

Classification statistics

Precision / F1

Precision = TP/(TP+FP). F1 = 2TP/(2TP+FP+FN). Precision is undefined when the model issues no positive predictions.

Example: The all-safe LLM has no defined precision in the 303-input comparison.

Classification statistics

MCC

Matthews correlation coefficient summarizes all four confusion counts: (TP*TN-FP*FN)/sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN)). Range -1 to +1; undefined denominator cases remain unavailable.

Example: MCC is a classification statistic. It is unrelated to Mac/macOS evaluation.

Classification statistics

Balanced accuracy / ROC-AUC / PR-AUC

Binary balanced accuracy averages recall and specificity (1-FPR). ROC-AUC summarizes score ordering across cutoffs. PR-AUC summarizes precision-recall behavior and depends on the evaluated class mixture.

Example: Strong ROC-AUC can coexist with poor decisions at one frozen cutoff.

Classification statistics

95% confidence interval

An interval produced by a specified sampling method. Group bootstrap resamples observed dependency groups; binomial/Wilson references use different assumptions. Neither supplies missing population coverage.

Example: A zero-error empirical bootstrap interval can collapse to zero without proving zero future error.

Classification statistics

McNemar test and Holm adjustment

McNemar compares the discordant errors of two classifiers on the same examples. Holm adjusts multiple pairwise p-values. Correlated campaigns can weaken the independent-pair interpretation.

Example: A significant difference on ID data does not repair an unassessed OOD gate.

Risk and reliability

2% FPR target and alert cutoff

The primary target permits at most the selected empirical false-alarm rate on the threshold-validation cohort. The cutoff is a model score, not the FPR itself. Test FPR can differ.

Example: With 1,000 legitimate validation messages, 2% corresponds to 20 alerts. It does not mean a score cutoff of 0.02.

Risk and reliability

Calibration and ECE

Calibration evaluates whether score levels correspond to observed positive frequencies in a population. ECE is a bin-weighted calibration gap under the benchmark's implementation. Low ID ECE does not guarantee valid real-inbox risk percentages.

Example: The later LLM's zero-slope calibration assigned the same mapped score to every usable output.

Risk and reliability

Valid-output rate and fail-open

Valid-output rate measures usable classifier answers. Under the frozen benchmark rule, an unusable answer receives zero score/no alert and still counts as invalid. The UI should show analysis unavailable.

Example: Readable software advice does not turn malformed LLM JSON into a valid classifier output.

Risk and reliability

Five-repeat consistency

The defined fraction of selected examples with valid, identical labels across all five repeated LLM runs. It measures repeatability of the specified output, not accuracy or prose quality.

Example: A consistently incorrect label can still be consistent; invalid outputs fail the criterion.

Risk and reliability

Human review

Actual people rate correctness, grounding, helpfulness and, for the later explanation layer, completeness. Automated quote/schema checks do not supply human ratings. Language comprehension matters.

Example: Earlier ratings cannot be copied onto a new prompt or explanation layer.

Risk and reliability

Hard gates and weighted ranking

Hard gates are mandatory requirements. Only complete survivors enter the frozen weighted ranking. Missing evidence is not a pass; the owner's project selection is recorded separately.

Example: TF-IDF can be chosen for implementation while authentic OOD/adversarial qualification remains incomplete.

Latency and hardware

p50 / p95 / p99

Latency percentiles. p95 is the 95th-percentile boundary of the recorded timing sample; it is not a maximum or a performance guarantee. The history retains the source's quantile method or labels a derived method.

Example: The later complete Chrome cells use 100 timed validation messages after 10 discarded warmups.

Latency and hardware

Mean, population standard deviation, min/max

Mean averages saved durations; population standard deviation describes their observed spread; min/max are the smallest/largest recorded values. Derived summaries do not represent new test runs.

Example: An incomplete cell's saved inference samples remain diagnostic if cold trials failed.

Latency and hardware

Per-email / batch / amortized latency

Per-email measures one request. Batch latency measures a multi-email request. Amortized latency divides accumulated time by a count and is not a single-email percentile.

Example: The older OmniRoute p95_batch_ms must not be compared directly with Chrome per-email p95_ms.

Latency and hardware

Cold start and warmup

Cold definitions vary: checkpoint loading, fresh-page readiness or the full first operation. Later readiness trials can retain operating-system/driver caches. Warmup runs are discarded before the main timing sample.

Example: Model load time and navigation-to-ready time are separate fields.

Latency and hardware

WASM / WebGPU / JavaScript CPU

These are execution backends. A backend failure or timeout stays visible. JavaScript TF-IDF does not become a WebGPU model by changing a label.

Example: The neural candidates had separate WASM and WebGPU timing cells.

Latency and hardware

4x CPU throttling

Chrome CPU emulation applies a configured slowdown to browser CPU execution. It is not a fourfold slowdown of every component; the GPU and separate Python process are outside that control.

Example: The full explanation harness includes a Python roundtrip that CPU emulation does not throttle.

Latency and hardware

Timing scope

The recorded boundary of measurement. Python AIService time, local HTTP batches, browser model time and browser-clock model-plus-Python-explanation time are different quantities.

Example: The v6 full_path_ms includes loopback Python normalization and is not wholly browser-local installed-extension performance.

Latency and hardware

performance.now()

A high-resolution browser elapsed-time clock. A clock being in Chrome does not mean every measured operation executes inside the browser.

Example: A timed await of a loopback HTTP call includes that roundtrip.

Latency and hardware

JS heap / process RSS / download size

JS heap measures JavaScript-managed memory. RSS measures resident process memory. Download size measures transferred/required assets under the stated definition. These are not interchangeable.

Example: JS heap does not include all native GPU or Python memory.

Latency and hardware

MB / MiB / bytes

1 MB = 1,000,000 bytes. 1 MiB = 1,048,576 bytes. The history keeps source units and does not silently switch between decimal and binary units.

Example: A model-weights size can differ from required static download size, which also includes runtime assets.

Mac/macOS evaluation

Recorded Mac evaluation status

No macOS model benchmark measurements were found in the audited saved metadata. Mac rows are explicit coverage gaps with blank numeric results. Backend/CRUD tests on a Mac do not measure model accuracy or inference latency.

Example: No Mac accuracy, p95, cold-start, memory, Apple CPU/GPU or OS version is fabricated.

Mac/macOS evaluation

What a real Mac comparison needs

The same frozen model, prepared inputs, calibration and cutoffs, plus actual Mac model/CPU/GPU, macOS/Chrome versions, backend, power state, warmups and saved timing samples. Report unsupported backends as failures/unavailable.

Example: Windows results cannot be scaled by a guessed Apple-silicon speed multiplier.

CSV column dictionary

date_manila

Manila calendar date, including date-only source evidence.

timestamp_manila

Timezone-qualified Manila datetime, when a clock was recorded. Blank for date-only evidence.

record_type

Statistic, latency, gate, event, amendment, preparation or coverage gap.

protocol

Rules/version under which the evidence was produced.

run_id

Recorded execution or reporting identifier. Multiple rows often share one run.

model

Saved candidate key or paired comparison; not a newly invented registry ID.

dataset_role

Training/validation/test/diagnostic population role.

metric

The named statistic, observation or event.

value

Full numeric source value or explicit derived result; blank is not zero.

unit

Fraction, ms, seconds, count, bytes, MiB, p-value or other recorded unit.

ci_lower

Recorded lower 95% interval bound, if available.

ci_upper

Recorded upper 95% interval bound, if available.

status

Source outcome, including failed, excluded, unassessed or historical states.

availability

Whether value is numeric, unavailable/undefined or an event without a numeric value.

backend

Actual runtime/backend named in the evidence.

cpu_throttle

Recorded browser CPU emulation factor; not a hardware speed conversion.

sample_count

The relevant sample/cohort size; not a sum across duplicate metric rows.

threshold

Saved alert cutoff for this model/cohort.

record_id

Stable identifier within this exported history.

timestamp_utc

UTC normalization of a recorded timezone-qualified timestamp.

timestamp_raw

Original source timestamp text, preserving its written precision.

timestamp_precision

Recorded datetime, date only, timezone missing or not recorded.

timestamp_role

What that timestamp actually means; report times are not run starts.

timestamp_source

File and field supplying the timestamp.

started_at_utc

Recorded start where available; absent starts are not reconstructed from file modification time.

finished_at_utc

Recorded finish where available.

model_id

Recorded registry/checkpoint ID when applicable; local algorithms may have no registry ID.

model_revision

Recorded revision or model digest when available.

dataset_origin

Collected, synthetic, reconstructed or unassessed population description.

platform

Recorded operating system. Blank means unknown; macOS coverage-gap rows are not executions.

python_version

Recorded Python version for that context, when available.

chrome_version

Recorded Chrome version; does not imply installed-extension testing.

hardware

Recorded CPU/RAM/GPU facts, with prior-observation attribution when applicable.

ci_method

Method associated with the saved interval; group and independent-message intervals have different assumptions.

groups

Recorded dependency-group count where supplied.

value_origin

Recorded value or the explicitly named derivation from saved samples/timestamps.

measurement_scope

What the timing or statistic includes.

notes

Material caveats, interrupted states, variants and methodological history.

source_path

Relative evidence-file path under the project root.

source_pointer

JSON field path or 1-based CSV line/column reference.

source_sha256

SHA-256 of the evidence file when this history was compiled.

context_source

Associated metadata file used for environment/model context.

Technical references

The metric definitions are consistent with scikit-learn's model-evaluation documentation. Score interpretation is discussed in its calibration guide. Browser elapsed-time clock semantics are defined by W3C High Resolution Time. See Chrome's Performance panel documentation for performance tooling. The saved protocol/source records govern the actual historical implementations.
